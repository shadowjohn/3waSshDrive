# 本機 SSH Server 與 Windows 帳號／公鑰管理設計

- 日期：2026-09-29
- 狀態：需求方向已確認；本文件供設計 review，尚未開始實作或修改 Windows 設定。
- 已確認需求：本機同時提供 SFTP 傳檔與完整 SSH 終端機；使用 Windows 原生帳號與密碼；可啟動／停用服務；公鑰管理、來源 IP 白名單、三個功能頁籤、bubble 新增／編輯、密碼失敗分段封鎖及保留七天的 grid 事件紀錄都是第一版必要功能。
- 已確認計次補充：存在的 Windows 帳號按來源 IP＋帳號分開計次；同 IP 對不存在帳號的密碼失敗共用計次，任何一組達門檻即封鎖整個 IP。
- 以下服務操作、權限邊界與驗收方式是依已確認方向整理的設計提案。

## 1. 目的與架構

3waSshDrive 新增「本機 SSH Server」管理頁面，由 Windows OpenSSH 的 sshd 服務處理登入、加密、SFTP 與終端機。既有 SSH.NET／WinFsp 遠端磁碟掛載流程保留；不要求升級 .NET Framework 4.7.2，也不自行實作 SSH 協定。

```text
3waSshDrive WinForms（一般使用者權限）
    +-- 「掛載遠端」頁籤：既有遠端掛載功能，維持目前使用者的一般權限
    +-- 「本機 SSH Server」頁籤：Server 狀態與設定
            +-- 權限允許的唯讀查詢：服務、帳號、診斷
            +-- 按需提權唯讀查詢：其他帳號的公鑰清單
            +-- 按需 UAC 管理操作：服務／帳號／公鑰／設定
                    +-- Windows SCM、帳號與 ACL API
                    +-- Windows OpenSSH sshd
                            +-- SFTP
                            +-- 以登入使用者身分執行 PowerShell
    +-- 「事件紀錄」頁籤：合併授權範圍內的遠端／本機／網路事件

3waSshDrive.ServerGuard（獨立 Windows Service）
    +-- 監聽受管 OpenSSH 登入事件
    +-- 密碼失敗計次／封鎖階段／到期排程
    +-- 僅操作受管 sshd 的來源 IP 封鎖規則
    +-- 持久化狀態與事件游標
```

sshd 與 ServerGuard 獨立於桌面程式運作。關閉、登出或更新 3waSshDrive UI 不主動停止兩個服務；實際登出情境的連線與封鎖持續性列入驗收。Server 管理本身不需要 WinFsp。ServerGuard 是為本次精確分段封鎖需求新增的固定用途背景元件，不是一般遠端管理命令入口。

第一版先管理本機標準帳號。既有帳號須明確加入管理範圍，不能因為列出帳號就重設密碼或改寫公鑰。管理員、網域、Microsoft／Entra 帳號不在第一版寫入範圍。暫不提供刪除 Windows 帳號／個人檔案、強制踢除既有會話、網路磁碟再分享、對外 NAT 設定及 SSH 憑證管理。

## 3. 服務操作的精確語意

| 操作 | 必須確認的結果 |
|---|---|
| 啟動服務 | 若為 Disabled，將啟動類型改為 Manual，再啟動；若原為 Automatic 則保留。等待 Running 並核對監聽結果 |
| 停止服務 | 停止目前 listener，保留啟動類型；確認 Stopped 與無新的 listener，不宣稱已終止所有會話 |
| 停用服務 | 停止服務並設為 Disabled；兩項各自驗證，部分失敗要如實顯示 |
| 開機自動啟動 | 設定 Automatic；不自動啟動當下已停止的服務 |
| 關閉開機自動啟動 | 設定 Manual；不自動停止目前正在運行的服務 |

Windows OpenSSH 官方曾明列：停止 sshd 可保留已建立的 SSH 連線。因此「停止／停用」表示停止接收新連線；第一版不承諾強制終止既有 SSH／SFTP 會話。實際 Windows／OpenSSH 版本上的結果須驗收並記錄。[官方行為說明](https://github.com/PowerShell/Win32-OpenSSH/issues/1681)

操作期間禁止同時送出相反的服務命令。逾時、UAC 取消、無權限、服務消失或外部狀態變更皆重新查詢並顯示實際結果，不只依程序 exit code 或請求已送出判定完成。

## 4. Windows 帳號與密碼

- 帳號以 Windows SID 識別，顯示名稱只供 UI 使用；建立專用帳號預設為標準使用者，不加入 Administrators。
- 密碼由 Windows 驗證與保存；不是 Windows Hello PIN。建立／重設時只在必要操作期間使用，不寫入 profiles.json、設定、暫存檔、命令列、環境變數或 log。
- 密碼輸入與 Windows 帳號操作由短生命週期的提權管理介面處理，避免經一般文字 IPC 傳遞密碼。遵守 Windows 密碼原則，不以空密碼繞過。
- 「允許 SSH 登入」由專用本機群組與 sshd 存取規則管理。「禁止 SSH 登入」只撤除 SSH 登入資格，UI 不將它描述為停用整個 Windows 帳號。
- 重設密碼確實會改變該 Windows 帳號在其他使用情境的密碼，操作介面需明示帳號與影響。
- 「只允許公鑰」只限制 SSH 認證，Windows 帳號的密碼仍然存在。
- 已認證會話不因移除公鑰或撤除 SSH 登入資格而被保證即刻終止；撤銷驗證使用全新連線。

## 5. 公鑰管理

### 5.1 使用流程

選擇受管帳號 → 貼上一行 OpenSSH 公鑰或選擇 .pub → 驗證格式 → 顯示類型、SHA-256 指紋、備註 → 新增。

- 同帳號可保留桌機、筆電等多把 key；按實際 key blob 去重，備註不作為識別依據。
- 新匯入先支援普通 Ed25519、RSA 與 ECDSA 公鑰；須通過格式／長度與已安裝 OpenSSH 的支援檢查。RSA 公鑰不等於必須啟用 SHA-1 ssh-rsa 簽章。
- 新增介面不接受任意 authorized_keys options、SSH 憑證、DSA、PEM／OpenSSH 私鑰或 PuTTY PPK 私鑰。PuTTY 使用者可貼上其 OpenSSH 格式公鑰。
- Server 管理只接收公鑰；不讀取、匯入或複製用戶端私鑰，也不碰 Codex／瀏覽器登入資料。
- 移除操作列出所選指紋；「只允許公鑰」且只剩一把 key 時，要求先補上另一把、改回密碼登入或明確禁止該帳號 SSH，避免意外鎖定。
- 公鑰能解析、成功寫檔、ACL 正確與成功登入是不同驗證層次，UI 分開顯示；不要求把私鑰交給管理程式才能測試。

### 5.2 檔案位置與權限

遵循標準帳號實際 profile 下的 .ssh/authorized_keys，不直接猜測 C:/Users/帳號名稱。新帳號尚無 profile 時，由 Windows profile API 建立／取得路徑；失敗則維持未開放 SSH 狀態。[Windows CreateProfile](https://learn.microsoft.com/en-us/windows/win32/api/userenv/nf-userenv-createprofile)

標準帳號與管理員的預設 key 位置不同，管理員可能使用共用的 administrators_authorized_keys。第一版拒絕把管理員當成普通帳號編輯；每次寫入前重新檢查 SID、群組與實際生效的 AuthorizedKeysFile。[Microsoft 公鑰管理](https://learn.microsoft.com/en-us/windows-server/administration/openssh/openssh_keymanagement)

檔案 owner／ACL 使用 SID 處理，不能授予其他一般使用者寫入權。提權操作不得跟隨使用者可控制的 junction／symlink／reparse point 寫入其他位置；實作必須驗證最終目標並防止檢查後替換路徑的競態，無法保證時停止該操作。

既有 authorized_keys 的未知行、進階 options、編碼及換行均保留。只增刪明確識別的目標項目；若存在同 key 不同 options 的多筆項目，不合併或一併刪除。寫入前比對外部修改，使用受限權限的同目錄暫存檔及原子替換，替換後重新驗證 ACL。備份與暫存資料不能成為權限較寬的副本。

## 6. OpenSSH 設定與既有安裝

以 Windows 選用功能提供的 OpenSSH 為第一版基準，保留 Microsoft 維護與更新路徑。缺少 Server 時顯示 Windows 安裝引導；第一版不打包另一份 sshd，也不自動下載測試版本。[Microsoft 安裝說明](https://learn.microsoft.com/en-us/windows-server/administration/openssh/openssh_install_firstuse)

- 先確認服務實際執行檔、參數、版本及設定位置；不把 PATH 找到的任意 sshd 當成管理目標。
- 新初始化採專用群組 allowlist、拒絕管理員登入、SFTP 與 PowerShell、手動啟動；不默認開放所有 Windows 使用者。內建 Administrators 群組由 SID 取得本機名稱，再產生正確的 DenyGroups 規則，以涵蓋帳號日後被加入管理員群組的情境。
- 既有自訂 sshd 設定預設唯讀檢視。第一版只接管能辨識並驗證相容性的設定；無法解析的 Include、Match 或存取規則不以覆寫方式處理。
- 首次納管提供實際設定差異。只改受管範圍，保留未知內容、原始編碼、換行與既有 host keys；Host key 私鑰不進入 app 設定或 log。
- 寫入前備份並校驗外部修改；候選設定先以 sshd -t 檢查，再以 sshd -T -C 核對代表帳號的有效 allowlist、key 路徑與認證模式。
- 每帳號的「只允許公鑰」使用有效的 Match 規則限制為 publickey；至少有一把有效公鑰才可設定。套用前提示尚未實際登入測試的狀態。
- 設定需重啟才生效時，介面提供明確的「套用並重啟」操作，顯示可能影響連線；保存草稿不等於已生效。
- 啟動失敗須能恢復原設定，且不能意外啟動原本停止的服務；回復失敗明確顯示，不宣稱已回復。

## 7. IP 白名單、網路與終端機權限

### 7.1 使用行為

- 第一版採整個 Server 共用的遠端來源白名單，所有受管帳號、密碼登入、公鑰登入、SSH terminal 與 SFTP 都適用；不只限制管理介面。
- 可新增／移除多筆單一 IPv4、IPv6 或 CIDR，例如 192.168.1.20、192.168.1.0/24。輸入先驗證、正規化及去重；CIDR 有 host bits 時顯示並要求確認實際網段，不默默擴大範圍。
- 第一版不接受網域名稱、萬用字元、Any 或全網段 /0。來源 IP 使用 Server 實際看到的連線來源；有 NAT、VPN 或跳板時，可能不同於用戶端本機 IP，UI 說明此點。
- 初始狀態只綁定 loopback。沒有遠端白名單時維持／回復只允許本機測試，不能把空清單轉成允許所有來源；loopback 例外須明確顯示。
- 新增白名單不自動開放網路；「套用並開放」明確呈現 Port、介面 profile 與來源範圍。第一版提供 Private profile 的受限開放，不自動開啟 Public profile 或設定路由器轉發。
- 移除 IP 只承諾阻止套用生效後的新連線／登入；既有連線不宣稱已被強制中斷。UI 同時顯示草稿、已生效清單與驗證狀態。

### 7.2 執行與驗證

防火牆在受管 TCP Port／sshd 範圍使用明確的 RemoteAddress 白名單；OpenSSH 另外以 AllowUsers 的來源 IP／CIDR 條件配合受管 AllowGroups，限制准許登入的帳號來源。兩層使用同一份正規化清單，避免只靠新增一條窄防火牆規則就宣稱已完成限制。[Windows RemoteAddress](https://learn.microsoft.com/en-us/powershell/module/netsecurity/new-netfirewallrule)、[OpenSSH AllowUsers](https://man.openbsd.org/sshd_config#AllowUsers)

- 套用前核對防火牆啟用狀態、effective policy、profile、預設入站行為及重疊的允許／封鎖規則，包含舊的 OpenSSH 規則與群組原則。不能默默修改其他工具或管理者的規則；有無法安全處理的衝突時不開放新的範圍，顯示需處理的規則及目前仍生效的狀態。
- 不建立覆蓋白名單的「全部封鎖」規則：Windows 明確 Block 可壓過 Allow。應依既有有效政策採 default-deny 與窄 Allow，不能擅改整台電腦的預設入站政策。[Windows 防火牆優先順序](https://learn.microsoft.com/en-us/windows/security/operating-system-security/network-security/windows-firewall/rules)
- OpenSSH 的既有 AllowUsers 條目可能累加；舊的無來源限制條目或 Match 規則不能繞過新白名單。若無法保留原設定並證明受管帳號都受來源限制，拒絕套用，不只在檔案尾端追加規則。
- IPv4 與 IPv6 一起驗證，不能只限制 IPv4 而留下 IPv6 入口。對 loopback、白名單內／外代表來源分別檢查候選 sshd 設定，並以全新實際連線驗證結果。
- 先驗證候選規則，採不擴大權限的套用順序，重啟後回讀兩層有效狀態；部分失敗時不顯示已生效。無法完成回復時停止新登入的 listener，清楚回報，不能留下已知較寬的放行狀態繼續聲稱安全。
- 「TCP 已擋住」、「SSH 認證拒絕」與「合法來源成功登入」分開記錄；若 firewall 被停用，OpenSSH 的登入限制不能被宣稱等同封包已被防火牆攔截。
- 白名單代表可以嘗試登入，不代表豁免暴力嘗試防護。第 9 節的暫時來源 IP Block 優先於白名單 Allow；與禁止建立覆蓋所有來源的永久 Block 是不同用途。

### 7.3 終端機權限

完整終端機依登入使用者的 Windows／NTFS 權限執行。「起始資料夾」不構成沙箱；SFTP chroot 不能被宣稱也限制 PowerShell。公鑰登入亦不代表自動取得連往其他 Windows 機器／SMB 的可委派密碼憑證。[Windows Server 設定](https://learn.microsoft.com/en-us/windows-server/administration/openssh/openssh-server-configuration)、[公鑰認證限制](https://learn.microsoft.com/en-us/windows-server/administration/openssh/openssh_keymanagement)

## 8. 功能頁籤與 bubble 表單

### 8.1 分頁與增編操作

主視窗維持共用標題、更新入口、系統匣及狀態列，主內容分成「掛載遠端」「本機 SSH Server」「事件紀錄」三頁。切頁不重建連線物件、不卸載磁碟、不停止重連或本機服務，各頁保留自己的選取、篩選與草稿。

- 遠端頁先沿用 Profile fleet、連線欄位與掛載操作，避免把新 Server 功能混入既有表單。遠端 Profile 的既有驗證、信任主機指紋與掛載語意保留。
- 本機頁上方是服務狀態、Port、開機啟動與啟停；下方以區塊呈現帳號／選定帳號的公鑰、IP 白名單、目前封鎖與登入紀錄，避免層層巢狀頁籤。
- 本輪新增的帳號、公鑰、白名單清單以 bubble 增編；既有遠端完整表單不在同一輪強制重做。bubble 是有標題、輸入欄位、儲存／取消的 owned 小視窗，靠近觸發按鈕或資料列，不能使用失焦即消失的 tooltip 充當表單。
- 帳號新增包含名稱與登入方式；既有帳號以 SID 辨識，編輯不偷偷更名或重設密碼。公鑰編輯備註與「替換公鑰」分開，替換前後顯示指紋。IP 編輯同時顯示原值、正規化結果及實際放行範圍。
- 必填、帳號重複／不合法、私鑰誤貼、公鑰重複、IP／CIDR 錯誤等在欄位旁說明，附可用範例。輸入中不連續跳 MessageBox；離開欄位或提交時驗證，提交失敗將焦點移到第一個錯誤。
- 正常欄位可去除首尾空白，密碼不能自動 trim。UI 預檢後，真正提交前仍回讀 Windows／檔案／防火牆，防止競態與覆蓋外部修改。
- 同時只開一個編輯 bubble；輸入中不改系統狀態。點外部或 UAC 導致失焦不自動儲存或丟棄；取消／切頁有未儲存變更時可保留非機密草稿或明確捨棄。驗證、權限或系統操作失敗時保留非機密輸入。
- 密碼仍由提權短生命週期介面處理；取消後不跨視窗保存或自動回填密碼。UAC 取消保留帳號名、公鑰及 IP 等非機密草稿，不顯示成已建立成功。
- Tab／Shift+Tab 依欄位順序移動；Enter 只執行目前 bubble 的明確提交，多行公鑰輸入時 Enter 保持編輯；Esc 進入取消流程。關閉後焦點回原按鈕／資料列。
- 目前主視窗的 AcceptButton 是遠端 Test & Mount；切到本機頁或開 bubble 時必須切換／清空，避免 Enter 意外掛載遠端磁碟。WinFsp 缺失只限制遠端頁，不阻擋本機 Server。
- 套用期間防止重複提交、顯示進度；只有回讀已落地的結果後才更新列表。部分成功要明確顯示已完成的步驟，不能一律回報成功或重送建立帳號。
- bubble 配合現有視覺樣式，在高 DPI、小視窗及多螢幕邊緣保持欄位、錯誤文字及操作按鈕可見；不改用吉祥物的台詞氣泡容器。

### 8.2 事件紀錄 grid

第三個頁籤上方顯示「目前封鎖 IP」，下方集中呈現遠端掛載與本機 Server 的歷史事件，採唯讀 grid，不要求使用者到磁碟尋找 log。歷史預設最新事件在上；日期、類型與關鍵字為直接可見的查詢欄位，來源、結果／等級、帳號與 IP 可展開進階篩選。依查詢分頁或串流載入，不能將全部七天資料一次塞入 UI thread。

| 欄位 | 內容 |
|---|---|
| 時間 | 儲存 UTC，畫面用本機時間並標示時區，包含秒數 |
| 來源 | 掛載遠端／本機 Server／Windows 網路／Guard |
| 事件類型 | 連線中斷、重連開始／成功／失敗、連線進入、登入成功／失敗、封鎖／解封、服務狀態等 |
| 結果／等級 | 進行中、成功、失敗、警告；文字與顏色並用 |
| 對象 | 遠端 Profile 或本機帳號；不存在帳號依安全處理後的嘗試名稱顯示 |
| IP／Port | 實際事件的遠端主機或來源 IP，不能從不可靠的錯誤字串猜測 |
| 摘要 | 簡短原因、錯誤碼、失敗計次或封鎖期限 |

顏色用於事件標籤／狀態圖示與淡色提示，保留可讀的文字對比；同時顯示事件名稱與結果，不能只靠整列底色辨識。

| 顏色 | 代表事件 |
|---|---|
| 藍色／中性色 | 一般資訊、連線進入、重連開始、規則待套用 |
| 綠色 | 登入／重連成功、確認解除封鎖 |
| 橙色 | 連線中斷、密碼失敗計次、警告或狀態待核對 |
| 紅色 | 已封鎖、重連失敗、封鎖／解封套用失敗等異常 |

「已封鎖」與「封鎖失敗」雖同用紅色，必須以不同文字／圖示呈現；歷史列明確表示當時結果，不能暗示該 IP 至今仍被封鎖。

- 日期可選起訖日，並提供「今天」「最近 24 小時」「最近七天」快捷範圍，預設最近七天。日期按畫面標示的本機時區換算 UTC，自起日零時至迄日次日零時前；起日大於迄日即在欄位旁提示。查詢取所選範圍與最近 168 小時的交集，顯示實際可查範圍，不能把已過保存期限顯示成從未發生事件。
- 類型支援多選，同類型選項間為 OR；日期、類型、關鍵字及其他篩選條件間為 AND。關鍵字依文字包含比對安全處理後的帳號、Profile、IP 與摘要，忽略字母大小寫，不執行正規表示式或指令；空白關鍵字視為未限制。提供「查詢」「重設」；重設回最近七天、全部類型、無關鍵字及無進階條件。
- 時間欄預設「新至舊」，可切換「舊至新」並顯示排序方向；先合併授權範圍內的來源、套用篩選與全體排序，再分頁。同一時間以穩定且唯一的事件 ID 決定順序，不能只排序當頁；查詢或排序改變時回第一頁。
- 點選一列可展開唯讀明細，包含事件 ID、關聯操作、UTC／顯示時間與安全診斷；複製只取安全欄位，不提供編輯原始紀錄。
- 歷史 grid 提供重新整理與自動更新開關；有新事件時不搶走正在閱讀的分頁、選列或捲動位置，可顯示「有新事件」提示。讀取下一頁沿用同一查詢快照／游標，避免新資料插入造成重複或跳列；重新整理才載入新快照，過期資料仍依 168 小時規則排除。暫停歷史畫面更新不停止事件保存、防護或目前封鎖清單更新，設定的篩選與排序在切頁後保留。
- 使用結構化事件模型，不從 SetStatus 文字反向解析。遠端 client 的 UI 心跳與 SFTP 操作層透明重連都要提供事件，以連線／關聯 ID 去重；同一斷線不能每次心跳都變成新的斷線事件，也不能漏掉 UI 輪詢間已完成的短斷線重連。
- 遠端 SFTP 斷線記錄為「連線中斷」並保留已知原因。只有 Windows 真正回報網路狀態變化才顯示對應網路事件，不能因單一 SSH timeout 就宣稱整台電腦斷網。
- 「連入」與「登入成功」分開：TCP／SSH 連線建立不等於通過帳密或公鑰驗證。若該 OpenSSH 版本沒有可驗證的連線進入事件，只顯示已取得的認證事件，不捏造連入紀錄。
- SFTP 認證成功不代表檔案已傳輸成功；第一版記錄連線與認證生命週期，不逐檔記錄檔名或收集終端機命令內容。
- 重連開始、成功與失敗分別記錄；排入重連工作不等於重連完成。封鎖決策、規則套用成功／失敗、到期解封及人工解封都有可追查的關聯事件，與第 9 節計數去重一致。
- 沒有資料、無權限讀取、Guard 離線、查詢失敗與正在載入使用不同狀態；不能將讀取失敗顯示為零事件。

「目前封鎖 IP」區塊獨立於歷史 grid：

- 從 Guard 取得已與受管防火牆規則核對的最新狀態快照，不從七天歷史中的封鎖／解封事件反推。日期、類型、關鍵字及進階篩選只影響歷史表格，不能隱藏仍在封鎖中的 IP。
- 顯示來源 IP、觸發帳號或「不存在帳號共用計次」、原因、五分鐘／一小時階段、開始時間、預定解除時間、剩餘時間及實際套用狀態。預設最近觸發在上，獨立分頁並顯示已核對封鎖總數及待處理／異常數。
- 「待套用」「已封鎖」「套用失敗」「解除中」「解除失敗」分開；倒數歸零改顯示「已到期，待確認解除」，不能自行移除資料列或宣稱已解封。確認受管規則移除後才離開清單，歷史事件仍按保存期限可查。
- 顯示上次成功核對時間並提供重新整理。Guard 離線或查詢失敗時可保留上次快照，但須標示「資料未更新／狀態未知」；沒有成功快照時不顯示零封鎖，陳舊倒數也不能當成目前防火牆狀態。
- 可點選 IP 查看其歷史，明確將歷史查詢切為最近七天、該 IP、全部類型及無關鍵字／其他條件；目前封鎖清單不受此操作影響。每筆已確認封鎖的 IP 列提供第 9.4 節的「立即解 ban」按鈕；只有紀錄讀取權者不能執行。

### 8.3 七天保存與資料權限

- 「七天」定義為最近 168 小時；查詢立即排除過期事件，啟動及至少每小時執行磁碟清理。電腦關機期間不承諾背景清理，恢復後補做。
- 第一版採按 UTC 日期分檔的 UTF-8 JSONL 事件儲存，單一寫入者追加、以穩定事件 ID 去重並支援串流／分頁讀取；過期邊界檔案以原子方式清理。這是獨立事件資料，不依賴畫面記憶體中的 grid。
- 遠端 client 事件存於目前使用者的 %LocalAppData%/3waSshDrive/events；本機 Server／Guard 事件由背景服務存於受保護的 %ProgramData%/3waSshDrive/events，UI 關閉期間仍持續記錄本機事件。
- 縮至系統匣仍保存 client 事件；真正 QUIT 後既有 client 磁碟已卸載，停止產生遠端 client 事件是正常生命週期，不代表本機 Server／Guard 也停止。
- ServerGuard 提供固定用途、具範圍與筆數上限的唯讀事件查詢，依 caller SID 授權本機管理員或管理員明確指定的紀錄讀取者；讀取權不包含修改帳號／防火牆。一般 UI 不直接放寬機器層級事件檔 ACL。遠端 client 事件只讀目前使用者的儲存範圍。
- 重啟 UI／Guard 後仍可查詢尚未到期的事件；原生 OpenSSH 事件來源可能因系統日誌輪替遺失，Guard 需及時接收並持久化，發現缺口要顯示資料不完整。
- 七天清理只影響本功能的事件紀錄，不刪除 Windows 原生事件日誌或既有 CrashLogger 檔案。封鎖期限、再犯階段與計次游標是另行維護的操作狀態，不能因事件滿七天被刪除就重置防護。
- 事件不包含密碼、私鑰、完整公鑰、完整設定或未過濾例外內容；帳號／IP 是經授權管理者查看的必要診斷資料。惡意帳號文字必須安全呈現且不能注入額外列。
- 磁碟滿、檔案權限錯誤或日誌損壞必須回報；不得無提示提前刪除七天內資料，亦不得以紀錄寫入成功推論 SSH／檔案操作成功。

## 9. 密碼失敗分段封鎖

### 9.1 計次與狀態轉換

使用者指定：一分鐘內五次密碼失敗 ban 五分鐘，再次失敗 ban 一小時，有成功再重新開始；並確認「存在帳號分開計次、不存在帳號共用計次、達門檻封鎖整個 IP」。計次維度與實際封鎖範圍必須分開實作。

- 存在的 Windows 本機帳號：以 (正規化來源 IP, Windows SID) 為獨立計次桶，同一帳號的大小寫／等價名稱不能繞過計數。
- 不存在的帳號：同來源 IP 的所有不存在名稱共用一個 unknown-account 桶，每次實際密碼失敗加 1；不同 IP 不共用。不能以亂換假帳號避開門檻，也不能把同一事件在共用桶重複計算。
- 帳號是否存在以 Windows 本機帳號查詢為準，不能直接相信 OpenSSH 訊息中的 invalid user，因為帳號存在但 SSH 權限不符也可能被視為無效。查詢失敗是保護診斷錯誤，不等於帳號不存在；帳號新增／刪除及名稱正規化需驗證。
- 同 IP 的既有帳號 alice 錯 3 次、bob 錯 2 次不觸發；alice 自己達 5 次，或同 IP 對五個不存在的帳號各錯 1 次，才觸發整個來源 IP 的封鎖。
- 再犯階段與 banUntil 以 IP 為單位：首輪由任一桶達門檻觸發；五分鐘後該 IP 再有一次密碼失敗就升為一小時，不以改用其他帳號重回首輪五次門檻。
- 同來源 IP 有新的成功 password／publickey 登入後，清空該 IP 所有計次桶及再犯階段，其他 IP 不受影響。這是「有成功再重新開始」在 IP 封鎖範圍下的明確語意。
- IPv4 使用單一位址、IPv6 使用單一 /128，IPv4-mapped IPv6 正規化為同一 IPv4。同 NAT 出口使用者雖可分帳號計次，但任何一桶觸發後仍會一起被封鎖。

| 狀態／事件 | 必要行為 |
|---|---|
| 正常期密碼失敗 | 將事件歸入該 IP＋存在帳號桶，或該 IP 的 unknown-account 共用桶；各桶使用滑動 60 秒視窗 (t-60s, t]，不使用整點分鐘切桶 |
| 任一桶視窗內第 5 次失敗 | 該來源 IP 立即進入五分鐘封鎖決策；排程套用受管來源 IP Block 並核對生效 |
| 五分鐘到期 | 解除此次 Block，但保留再犯狀態；單純經過時間不重置成初犯 |
| 再犯期下一次密碼失敗 | 不論存在或不存在帳號，一次就觸發該 IP 一小時封鎖，不必再湊滿五次；之後到期再失敗亦封一小時 |
| 未封鎖／到期後有新的成功登入 | 同來源 IP 完成 password 或 publickey 認證後，清空該 IP 所有失敗桶與再犯階段，回到初始規則 |
| 正在封鎖 | 不因封包重試、拒絕摘要或舊事件而加次或延長；不接受舊連線／延遲成功事件直接解除 active ban |

五分鐘／一小時計時自守護服務提交該次封鎖決策時開始，採可測試時鐘；防火牆套用中的時間也必須可觀察。每個來源的事件依已驗證的事件順序序列化處理，成功不能重置其後已發生的失敗。若封鎖期間某條先前進入的連線完成認證，記錄競態但不據此清除當前 ban；到期後的新認證成功才重置。

### 9.2 事件來源與計數正確性

Windows OpenSSH 預設可寫 ETW／Event Viewer，Operational channel 提供 INFO 類事件。第一版固定採受管 sshd 的事件來源，將 Windows／OpenSSH 支援版本、實際 provider、事件 payload、來源 IP 與認證方法辨識作為實作前的窄 PoC 驗收；不能只比對 Event ID 或任意包含「failed」的文字。[官方 Logging Facilities](https://github.com/PowerShell/Win32-OpenSSH/wiki/Logging-Facilities)

- 只計實際 Failed password 事件，包括可歸屬到來源 IP 的無效帳號密碼嘗試。Invalid user 摘要、斷線、MaxAuthTries 訊息不能再重複算一次；公鑰探測／失敗、掃描或 TCP 中斷不算密碼錯誤。
- 只使用受管 OpenSSH 的登入成功事件重置；SFTP 檔案讀寫成功、開啟新 channel、既有終端機活動都不算重新登入。不得把 RDP、Windows 桌面或其他服務的失敗混入。
- 以事件 channel、日誌世代與 Record ID 去重；持久化游標與狀態須一致。重新啟動補讀事件而非從最新位置重新計零；日誌被清除、遺漏、格式不支援或切到 LOCAL0 時，顯示保護異常，不能繼續宣稱計次完整。
- 解析須依已驗證的 payload 結構，限制欄位長度並驗證 IP；帳號名稱、備註或錯誤文字不能被當成另一筆事件或任意封鎖目標。
- MaxAuthTries 是單連線限制，PerSourcePenalties 也不是上述滑動視窗與成功重置政策，不能以設定其中一個就聲稱達成需求；是否有其他原生限制生效需另行顯示。[OpenSSH 認證限制](https://man.openbsd.org/sshd_config#MaxAuthTries)、[PerSourcePenalties](https://man.openbsd.org/sshd_config#PerSourcePenalties)

### 9.3 背景生命週期、封鎖與復原

- ServerGuard 必須作為獨立 Windows Service 運行，不能依賴 WinForms Timer 或 UI 是否開啟。啟用受保護的遠端 listener 前，確認 Guard、事件來源與防火牆可用；只使用遠端掛載的人不需要安裝 Guard。
- Guard 的執行檔與依賴部署在受保護的機器層級目錄，服務設定／狀態只允許管理員與服務身分寫入；不能從使用者可寫的 Velopack 安裝目錄以高權限常駐執行。以獨立的按需提權安裝／更新流程管理，UI 更新不替換運行中的 Guard。
- Guard 只接受固定的狀態查詢與已授權管理操作，不提供任意命令、路徑或全機防火牆編輯。重啟、關閉 UI、重新開機不清空再犯紀錄；持久化 banUntil、階段、必要的失敗時間與事件游標，且不保存密碼。
- 封鎖只作用於受管 sshd 的 Port／程序範圍與該來源 IP，不封鎖該 IP 對整台電腦的其他服務。白名單內 IP 同樣會 ban；期間密碼、公鑰、SSH 與 SFTP 都受阻，不能靠公鑰穿越 IP Block 自行解 ban。
- Block 優先於 Allow，因此明確的短期來源 Block 可壓過白名單；仍需驗證有效政策、IPv4／IPv6 與規則實際生效。既有連線可能因 Windows 防火牆重新授權受到影響，不能承諾只擋新連線且絕不斷線。[Windows ALE 重新授權](https://learn.microsoft.com/en-us/windows/win32/fwp/ale-re-authorization)
- 事件通知、判定到防火牆生效是非同步流程，需量測延遲與並行突發；不能宣稱第五次失敗與封鎖是原子操作，或第六次嘗試必定尚未進入 sshd。
- 重新啟動時先對齊未到期 ban 與實際受管規則，再恢復正常監聽；到期只移除自己建立的規則。移除白名單、停止 sshd 或重啟 Guard 都不等於清空再犯狀態。時鐘調整、日誌重播與狀態檔損壞列入驗收，不能靜默恢復為全部未封鎖。
- Guard 可偵測的事件／持久化／防火牆失敗應回報並停止受管新登入 listener，保留故障資訊與既有封鎖。Guard 突然崩潰須由 SCM 故障恢復機制處理；事件補讀、恢復時效與仍可能存在的保護空窗須實測，不能宣稱已保證無空窗。正常停止／更新 Guard 前先停止 listener，復原後按原意圖恢復。
- Windows 自己的帳號鎖定政策仍獨立存在，可能更早鎖住帳號；程式只顯示診斷，不為配合 IP ban 而降低該政策。IP 解 ban 不代表 Windows 帳號已解鎖。[Windows 帳號鎖定](https://learn.microsoft.com/en-us/previous-versions/windows/it-pro/windows-10/security/threat-protection/security-policy-settings/account-lockout-threshold)

### 9.4 操作介面

「事件紀錄」頁提供第 8.2 節的目前封鎖清單；本機 Server 頁的封鎖摘要共用同一 Guard 狀態來源，並可導向完整清單。每筆已確認封鎖的 IP 列都有「立即解 ban」按鈕，提供本機管理員直接要求解除，無須等待五分鐘／一小時到期。

- 按鈕說明清楚標示「解除此 IP 封鎖，並重設失敗計次與再犯階段」；目標 IP 留在操作列上。只移除該 IP 的受管 ban、清空該 IP 所有計次桶並回到初犯規則，保留歷史事件，不更動其他 IP、IP 白名單或 Windows 帳號鎖定。
- 操作經固定用途的管理員授權入口送交 Guard，再次核對目標與實際規則；只有紀錄讀取權者不能執行。狀態未知時先重新核對，不能對陳舊清單宣稱解除成功。此本機復原入口不受 SSH IP ban 影響。
- 按下後該列顯示「解除中」並停用重複提交；確認規則移除且計次／階段重設已保存後，才移出目前封鎖清單並顯示成功。失敗保留該列與具體原因；部分成功分別顯示，不能把請求已送出當成已解封。操作不等待歷史 grid 下次刷新才更新結果。
- 記錄執行者、目標 IP、人工解封原因與實際結果；後續新登入失敗依重設後規則重新計次。人工操作與同 IP 的自動封鎖／解封須序列化，過期操作回應不能清掉後來新成立的 ban。

## 10. 程式整合與操作安全

### 10.1 管理員權限與遠端掛載隔離

目前 MainForm 的 MountProfileAsync 透過 Task.Run 呼叫 MountManager，並在同一程序建立 SSH.NET 連線與 WinFsp host；它不是隔離身分的掛載程序。若將整個 GUI 改成以管理員執行，掛載程式也會使用該高權限安全性內容。Windows 的一般／提權登入工作階段可能具有不同的磁碟代號對應，不能保證一般 Explorer 仍看得到提權程序建立的掛載。[Microsoft UAC](https://learn.microsoft.com/en-us/windows/security/application-security/application-control/user-account-control/how-it-works)、[磁碟對應與提權工作階段](https://learn.microsoft.com/en-us/troubleshoot/windows-client/networking/mapped-drives-not-available-from-elevated-command)

| 元件 | 權限與責任 |
|---|---|
| 3waSshDrive 主程式、SSH.NET client、WinFsp host | 目前互動使用者的一般權限；持有遠端 Profile 與 client 憑證、建立磁碟掛載 |
| 短生命週期管理 helper | 需要系統變更時單獨由 UAC 授權；只處理固定的帳號／服務／公鑰／受管防火牆操作或轉交管理請求 |
| ServerGuard | 受保護的機器層級 Windows Service，以具所需權限的服務身分計次與套用／移除 ban；不接管遠端磁碟掛載 |
| sshd 建立的 SSH／SFTP 工作階段 | 依通過認證的 Windows 帳號及其權限執行，與 GUI 或 Guard 的身分分開 |

- 主程式明確採 asInvoker，不使用 requireAdministrator／highestAvailable；服務操作不能以管理員重啟整個 GUI。asInvoker 仍會繼承啟動者的安全性內容，因此必須在自動／手動掛載之前檢查實際權限；若由管理員終端機或「以系統管理員身分執行」啟動，提示改從一般桌面啟動並阻止新掛載，不能把 asInvoker 當成已自動降權。
- 單獨啟動管理 helper 不會提升已在執行的主程式。完成、取消 UAC、提權失敗或 Guard 重啟皆不重啟 GUI、不卸載或轉交既有 client 掛載。一般使用者在 UAC 輸入另一位管理員憑證時，改變的是 helper 的身分，不能切換 GUI 的使用者、Profile 目錄或單例鎖定範圍。
- helper 與 Guard 使用受保護的部署位置和固定操作契約，依實際呼叫者 SID／權限授權，不相信訊息自報「我是管理員」。不接收任意命令、client 掛載要求、遠端密碼或私鑰，不代讀／搬移使用者的遠端連線設定。管理 helper 不負責啟動或更新一般權限 GUI。
- Guard 安裝／設定時走獨立提權流程；啟用後自動 ban／到期解封由服務依既定規則執行，不為每次密碼失敗跳 UAC。人工「立即解 ban」等寫入操作仍須管理員授權；事件讀取權與寫入權分開。
- 本機 Windows 執行身分與遠端 SSH 認證帳號是兩件事：目前 SSH.NET 使用 Profile.Username 及選定的密碼／私鑰。即使本機誤提權，也不會自動把遠端帳號變成 root／Administrator；但本機檔案權限、使用者資料路徑及磁碟可見性仍可能改變，故需上述隔離。
- 不藉改動 EnableLinkedConnections、關閉 UAC 或把 client 掛載搬進 SYSTEM 服務來處理磁碟可見性；先維持既有一般使用者掛載邊界並以桌面實測驗收。

### 10.2 其他整合與操作邊界

- 新增 Server 管理邊界，與既有 DriveProfile、ProfileStore、SFTP mount 分開；Windows、sshd 與 authorized_keys 是帳號與設定的實際狀態來源。UI metadata 只保存受管 SID 與必要資料；Guard 的封鎖狀態與事件游標依第 9 節獨立持久化。
- 普通 UI 查詢和按需提權操作分開；不新增接受任意命令的常駐管理員服務。提權入口只接受固定操作、重新驗證目標，不能由呼叫端指定任意可執行檔或寫入路徑。
- 一般權限無法讀取其他帳號公鑰時，顯示需要管理員權限，使用固定用途的提權唯讀操作，只回傳類型、指紋、備註與必要診斷；不能將無權限讀取顯示成沒有公鑰，也不能為 UI 查詢放寬 authorized_keys ACL。
- 操作序列化，帳號建立／profile／ACL／SSH 登入資格分階段處理；未完整完成前不開放登入。失敗記錄已完成步驟，不自動刪除帳號或使用者資料。
- Server 寫入操作加入既有 app 更新協調：UI 更新前不再接新的互動寫入，等待已開始的操作完成；未完成則取消 UI 更新。UI 更新與 self-check 不啟停 sshd／Guard、不修改帳號與公鑰，也不暫停 Guard 的計次或解封排程。
- log 可記錄操作、受管 SID／公鑰指紋、結果與安全的錯誤碼；不記錄密碼、私鑰、完整公鑰文字或未過濾的外部程序輸出。

## 11. 驗收與證據邊界

1. 建置與單元測試：服務狀態切換、設定差異／有效規則、公鑰驗證去重、保留未知行、外部修改偵測、更新互斥與失敗路徑。
2. 提權檔案操作測試：錯誤 SID、profile 缺失、ACL 不符、reparse point／路徑替換競態、原子寫入失敗時不改到錯誤檔案。
3. 隔離 Windows 測試環境：建立兩個標準帳號，完成 profile 與公鑰配置；分別驗證 Windows 密碼登入、publickey 登入、PowerShell 的 whoami 及 SFTP 上下載雜湊。
4. 公鑰案例：同帳號兩把 key 均可登入；移除其中一把後，使用被移除 key 建立全新連線須失敗，另一把仍成功。停用 agent 額外 key／密碼 fallback 與連線共用，避免假陽性。
5. 只允許公鑰案例：密碼認證失敗、公鑰成功；Windows 帳號密碼仍有效於其原本允許的本機用途。禁止 SSH 登入後，新的密碼與公鑰登入均失敗。
6. 服務案例：啟動、停止、停用、重開機與外部操作後的 UI 真實狀態；停用後新連線失敗，既有 SSH／SFTP 會話結果單獨記錄。
7. 網路案例：白名單內來源須能以正確帳號與密碼／公鑰使用 SSH 及 SFTP；名單外來源即使用相同有效憑證也不能登入。涵蓋 IPv4／IPv6、CIDR 邊界、空名單、刪除 IP、舊寬鬆 Allow 規則、GPO／firewall 關閉與部分套用失敗。至少用不同來源的實際區網連線驗證，不將 loopback 成功當成區網或 Internet 可用。
8. 回歸：既有遠端磁碟掛載、密碼不落盤、self-check、app 更新與獨立 sshd 存活；另外驗證現有 client 掛載 Windows SFTP 的路徑／metadata 相容性，未測前不宣稱雙向掛載完成。
9. 分頁／bubble 桌面驗收：三頁切換時掛載與重連仍運作；Server 不依賴 WinFsp；欄位錯誤、重複資料、私鑰誤貼、CIDR 修正、取消／失焦／UAC 失敗保留非機密草稿；鍵盤提交不觸發背景遠端掛載；高 DPI 與多螢幕操作可用。
10. 使用可注入時鐘測試封鎖狀態機：60 秒邊界、跨分鐘第五次、五分鐘到期、再犯一次即一小時、一小時後仍保留階段、成功清空同 IP 狀態、公鑰失敗不計次、不同來源獨立、同 IP 的存在帳號分開計次、不存在帳號共用計次、SID／名稱等價、存在但無 SSH 權限帳號的辨識，以及重複／延遲事件不誤解 ban。
11. 實際 OpenSSH 事件驗收：同連線多次密碼失敗、跨連線失敗、無效帳號、成功 password／publickey、SFTP 登入、公鑰探測與斷線摘要，確認每次正確歸屬且只計一次。驗收不得使用真人主要帳號試錯以觸發系統鎖定。
12. 實機封鎖：白名單內來源達門檻後密碼與公鑰都受阻、到期恢復可嘗試登入、成功後回初始階段、手動復原、IPv4／IPv6、既有會話影響、併發競態及從第 5 次事件到規則生效的延遲，各自留下證據。
13. Guard 生命週期：關閉 UI、UI 更新、Guard 崩潰／重啟、重新開機、日誌清除／LOCAL0 漂移、狀態損壞、時間改變、防火牆失敗與過期規則清理；驗證再犯階段不因重啟消失，且保護降級不能顯示正常。
14. 事件紀錄：實際斷線／重連、成功及失敗登入、ban／解 ban 均出現在 grid 且文字與顏色結果正確；驗證日期／多類型／關鍵字組合、空值與日期錯誤、重設、跨來源新至舊排序後分頁、同時間穩定排序、新事件不跳頁搶焦點、無權限／故障提示、UI 關閉後 Server 事件仍保存、重啟可讀取、UTC／時區及 168 小時邊界清理；清理不可重設再犯狀態，也不可刪除其他類型日誌。
15. 目前封鎖清單：歷史查詢與暫停更新不影響目前封鎖 IP 顯示；驗證 Guard／防火牆核對、待套用與失敗不冒充已封鎖、倒數歸零但解除失敗仍保留、陳舊快照及未知狀態提示、封鎖數量與歷史筆數獨立、點選 IP 查詢及管理員解除權限。逐列「立即解 ban」不等待期限，正確重設該 IP 計次與再犯階段、保留歷史，並處理重複點擊、部分失敗及同 IP 新 ban 的競態。歷史曾封鎖不等於目前仍封鎖，讀取失敗不等於目前零封鎖。
16. 權限隔離：一般桌面啟動並掛載後，以普通 Explorer／終端機讀取；操作服務、防火牆與立即解 ban 的 UAC 成功／取消／失敗前後，GUI PID、使用者 SID、權限層級及掛載維持不變。涵蓋管理員帳號的一般桌面與標準使用者輸入其他管理員憑證、手動高權限啟動在自動掛載前被攔截、Guard 重啟，以及遠端認證仍使用 Profile 帳號；不得只以建置成功代替登入工作階段／桌面磁碟可見性的實測。

目前只有程式碼與官方文件的可行性證據；以上測試尚未執行。實作驗收時逐項記錄已通過、失敗或未驗證的範圍，不以 API 回傳、設定寫入、服務 Running 或工作完成推論真人帳號已能登入。
